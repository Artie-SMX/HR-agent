# 基于 Qwen-Agent 的简历与岗位匹配分析 Agent

## 1. 项目定位

本项目是东华大学信息管理与信息系统专业社会实习任务 3.5 的轻量化 Demo。系统通过文档解析工具读取简历和岗位要求，提取可验证信息，分析两者的匹配程度，并为人工复核提供依据。

## 2. 目标功能

### 2.1 输入

- 简历电子 PDF；
- 简历扫描 PDF；
- 岗位 PDF；
- 直接粘贴的岗位文字。


### 2.2 文档处理工具

文档处理流程为：

```text
判断 PDF 类型 → 优先提取文字层 → 必要时 OCR → 转换为 Markdown → 保留页码和原文证据
```

- 带有效文字层的 PDF 优先直接提取文字；
- 扫描件或文字提取失败时调用 OCR；
- Markdown 结果保留文档类型、页码、标题、段落、项目分块和异常提示；
- OCR 或字段抽取应保留置信度，低置信度内容进入人工复核清单。

### 2.3 简历信息提取

提取以下信息：

- 最高学历；
- 学校名称；
- 学校层次；
- 专业；
- 在读状态；
- 毕业年份或年级；
- 技能；
- 奖项；
- 项目经历。

每段项目经历分别提取：项目名称和时间、业务场景、本人角色、承担任务、采取的行动、使用的技术或工具、项目结果和量化成果，以及对应的简历原文及页码。

原文没有出现的信息标记为“简历未提供”。

### 2.4 岗位信息提取

将岗位文本分为：岗位职责、必须条件、优先条件、学历要求、专业要求、毕业年份或年级要求、技能要求、项目或经历要求，以及其他与岗位工作直接相关的要求。

岗位没有提到的内容标记为“不适用”。若岗位出现毕业院校、年龄等可能与工作内容缺乏直接关系的限制，将会原文展示并标记为“需人工复核”。

## 3. Agent 处理流程

1. 判断输入文件类型；
2. 调用 PDF 文字提取工具；
3. 必要时调用 OCR 工具；
4. 调用 Markdown 转换工具；
5. 分别解析简历和岗位信息；
6. 区分岗位的必须条件、优先条件和岗位职责；
7. 对照简历证据逐项匹配；
8. 计算简历证据匹配分和信息完整度；
9. 按风险和匹配程度生成分析报告。

运行日志应记录 Agent 的工具调用过程，以证明系统实现了“模型判断 → 工具调用 → 获取结果 → 继续分析”的 Agent 流程。

## 4. 匹配状态

每项要求只能标记为以下一种状态：

- **匹配**：简历存在明确证据；
- **部分匹配**：存在相关证据，但范围、深度或熟练度不足；
- **不匹配**：简历信息与岗位要求明确冲突；
- **未知**：岗位有要求，但简历没有提供足够信息；
- **不适用**：岗位未提出该项要求。


## 5. 项目经历分析

每段项目分别从业务场景相似度、工作任务相似度、技能实际运用相关度、成果和产出相关度四方面分析，并引用具体项目原文解释判断。

技能栏中写明某项技能，但项目中没有对应应用证据时，分别标记为“技能声明”和“项目应用证据不足”。

## 6. 评分规则

### 6.1 默认权重

| 维度 | 权重 | 说明 |
|---|---:|---|
| 项目经历相关度 | 45% | 岗位任务的实际应用证据 |
| 技能匹配度 | 35% | 岗位要求技能的覆盖程度 |
| 学历匹配度 | 8% | 仅依据岗位原文判断 |
| 专业匹配度 | 7% | 相近专业允许部分匹配 |
| 年级或毕业年份 | 5% | 仅在校招、实习岗位中启用 |
| 学校层级 | 0% | 只提取展示，不参与默认评分 |

受到国家政策规范，学校名称和学校属性作为信息展示，只有岗位原文明确提出相关条件时，才列为人工复核事项。

### 6.2 门槛与加权分离

岗位明确写明的条件会单独进行门槛核验，不被项目经历高分抵消。

### 6.3 缺失值处理

- 岗位未提出：`N/A`，从评分分母中排除；
- 岗位有要求但简历没写：`unknown`；
- 简历明确不符合：`mismatch`；
- 有证据但不完整：`partial`。

当岗位不适用某个维度时，剩余维度按比例重新归一化。

### 6.4 两个输出指标

- **简历证据匹配分**：简历中已出现证据与岗位要求的匹配程度；
- **信息完整度**：岗位要求中能够从简历确认的比例。

两个指标必须同时展示，不能只输出一个看似精确的总分。

## 7. 输出结构

报告按以下顺序输出：

1. 最大风险项；
2. 岗位必须条件核验；
3. 未知信息和待确认事项；
4. 全部匹配项，按照匹配程度从低到高排列；
5. 项目经历逐项分析；
6. 技能匹配分析；
7. 简历证据匹配分；
8. 信息完整度；
9. 权重及计算过程；
10. 人工复核建议。

在人工复核环节，可根据岗位要求生成不超过 5 个面试追问。追问必须对应简历中缺失、模糊或需要验证的内容，不得代替录用判断。

每项结果应包含：匹配状态、对应维度、简历具体原文和页码、岗位具体要求和页码或段落、判断理由、OCR 或抽取置信度，以及是否需要人工复核。

## 8. 隐私与公平要求

- 测试阶段只使用虚构或匿名化简历；
- API Key 不得写入代码、README 或截图；
- 不提取或评分性别、年龄、民族、籍贯、婚育、照片等信息；
- 不根据缺失信息推断候选人能力；
- 不自动生成录用或淘汰结论；
- 所有结果均应支持人工检查和修改。

## 9. 技术方案

- 编程语言：Python 3.11；
- Agent 框架：Qwen-Agent；
- 模型服务：阿里云百炼/DashScope；
- 运行方式：Windows 本地运行；
- 编辑器：VS Code；
- 版本管理：Git；
- 第一版界面：命令行；
- 测试数据：虚构简历和岗位说明。

- 正常、字段缺失、内容模糊三组测试结果；
- 关键代码片段；
- 至少一个问题及解决过程；
- 操作文档；
- 最终输出报告。
